# Music Mood API 🎵

**Music Mood API** — небольшой учебный REST API на Python и FastAPI для просмотра каталога музыки и составления плейлистов под настроение.

Проект создан для итоговой работы по дисциплине «Инфраструктура и администрирование». Он демонстрирует полный цикл: разработка → Git → автоматические тесты → CI в GitHub Actions → запуск и диагностика.

## Что умеет сервис

- Показывает 12 композиций из демонстрационного каталога.
- Ищет треки по названию или исполнителю, фильтрует по жанру и настроению.
- Возвращает композицию по ID или понятную ошибку `404`.
- Собирает плейлист заданного настроения в рамках ограничения по времени.
- Показывает список жанров и количество треков в каждом.
- Проверяет работоспособность `/health`, версию `/version` и настройки `/info`.

Для запуска не требуются база данных, ключи Spotify, внешние API или Docker. Каталог хранится в файле `music_data.py` (продолжительности приблизительные и используются для демонстрации).

## 1. Установка

Нужен Python **3.12** (или совместимый Python 3.10+). Откройте терминал в папке репозитория.

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

### Windows (PowerShell)

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
```

`requirements-dev.txt` устанавливает также зависимости из `requirements.txt`. Для запуска без тестов достаточно `python -m pip install -r requirements.txt`.

## 2. Переменные окружения

Создайте свой `.env` на основе безопасного примера:

```bash
cp .env.example .env
```

На Windows можно выполнить `Copy-Item .env.example .env` в PowerShell.

| Переменная | Назначение | Пример / значение по умолчанию |
| --- | --- | --- |
| `APP_NAME` | Имя сервиса в документации и `/info` | `Music Mood API` |
| `APP_AUTHOR` | Автор в `/info` | `Никита` |
| `DEFAULT_PLAYLIST_MINUTES` | Лимит плейлиста по умолчанию, от 1 до 180 минут | `15` |
| `LOG_LEVEL` | Уровень логирования | `INFO` |

Если `.env` отсутствует, используются значения по умолчанию. Настройку `DEFAULT_PLAYLIST_MINUTES` можно передавать и прямо через переменную окружения. Некорректное значение заменяется на 15 и сопровождается предупреждением в логах.

> **Безопасность:** никогда не коммитьте настоящий `.env`, пароли или токены. `.gitignore` исключает `.env`; `.env.example` не содержит секретов.

## 3. Запуск приложения

Для разработки (автоматический перезапуск при изменениях):

```bash
python -m uvicorn app_final:app --reload
```

Для обычного запуска без `--reload`:

```bash
python -m uvicorn app_final:app --host 127.0.0.1 --port 8000
```

Откройте:

- http://127.0.0.1:8000/docs — интерактивная документация Swagger UI, где удобно нажимать **Try it out** и **Execute**;
- http://127.0.0.1:8000/ — стартовая страница API;
- http://127.0.0.1:8000/health — проверка доступности;
- http://127.0.0.1:8000/version — версия приложения.

Для остановки сервера нажмите `Ctrl+C` в терминале.

## 4. Маршруты и примеры

| Метод и адрес | Описание | Пример |
| --- | --- | --- |
| `GET /` | Информация о сервисе | `/` |
| `GET /health` | Проверка работоспособности | `/health` |
| `GET /version` | Текущая версия | `/version` |
| `GET /info` | Название и автор из переменных окружения | `/info` |
| `GET /tracks` | Полный каталог + фильтры | `/tracks?genre=pop&mood=calm` |
| `GET /tracks/{track_id}` | Трек по идентификатору | `/tracks/2` |
| `GET /genres` | Список жанров и количество треков | `/genres` |
| `GET /playlist` | Подбор по настроению и времени | `/playlist?mood=calm&max_minutes=10` |

Дополнительные примеры:

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/version
curl http://127.0.0.1:8000/tracks
curl "http://127.0.0.1:8000/tracks?q=queen"
curl "http://127.0.0.1:8000/tracks?genre=rock"
curl http://127.0.0.1:8000/tracks/2
curl http://127.0.0.1:8000/genres
curl "http://127.0.0.1:8000/playlist?mood=calm&max_minutes=10"
```

Доступные настроения: `calm`, `upbeat`, `energetic`, `focus`. При неизвестном ID или настроении сервис возвращает `404`, а при неправильной длительности — `422`. Плейлист подбирается по порядку композиций из каталога, без превышения выбранной длительности; при слишком маленьком лимите он может оказаться пустым.

**Пример ответа на запрос `GET /playlist?mood=calm&max_minutes=10`:**

```json
{
  "mood": "calm",
  "max_minutes": 10,
  "total_seconds": 469,
  "track_count": 2,
  "tracks": [
    {"id": 3, "title": "Yellow", "artist": "Coldplay", "genre": "rock", "mood": "calm", "duration_seconds": 269},
    {"id": 6, "title": "ocean eyes", "artist": "Billie Eilish", "genre": "pop", "mood": "calm", "duration_seconds": 200}
  ]
}
```

## 5. Автоматические тесты

Запустите из корня репозитория (в активированном виртуальном окружении):

```bash
python -m pytest -v
```

Проверяются: `/health`, `/version`, каталог, поиск, фильтрация, ID, генерация плейлиста, ограничения длительности, обработка ошибок, переменные окружения. Успешное выполнение заканчивается сообщением `passed`.

## 6. GitHub Actions / CI

Workflow `.github/workflows/ci.yml` автоматически запускается при **push** и **pull request**:

1. Загружает исходники репозитория.
2. Устанавливает Python 3.12 и зависимости.
3. Запускает `python -m pytest -v`.
4. **После успешных тестов** публикует artifact `music-mood-api` с файлами приложения.

Статус проверки: вкладка **Actions** вашего GitHub-репозитория → последний запуск **Music Mood API CI** (зелёная галочка) → раздел **Artifacts**.

## 7. Диагностика и логи

Основные события пишутся через модуль Python `logging` в **терминал, из которого запущен uvicorn**:

- запуск сервиса и количество треков;
- HTTP-метод, путь и статус запроса;
- найденное число треков;
- создание плейлиста;
- предупреждения для ошибок и неверных настроек;
- остановка приложения.

**Проверка здоровья:** `curl http://127.0.0.1:8000/health` → `{"status":"ok"}`.

**Проверка версии:** `curl http://127.0.0.1:8000/version` → `{"version":"1.0.0"}`.

| Проблема | Что проверить |
| --- | --- |
| `ModuleNotFoundError` | Активировано ли `.venv`? Выполнено ли `python -m pip install -r requirements-dev.txt`? |
| `Connection refused` | Запущен ли сервер? Правильный ли порт `8000`? |
| `Address already in use` | Порт занят другим процессом: остановите его или используйте `--port 8001`. |
| `404` для `/tracks/999` | Это ожидаемо: записи с таким ID нет. |
| `422` для `max_minutes=0` | Это ожидаемо: допустимые значения от 1 до 180. |
| Изменения `.env` не применились | Перезапустите сервер. |
| Тесты красные на GitHub | Откройте **Actions → последний запуск → Run tests**, прочитайте текст ошибки. |
| Не появился artifact | Он публикуется только после успешно выполненных тестов. |
